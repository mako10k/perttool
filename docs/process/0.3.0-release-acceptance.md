## 3. Distribution and default installation

The beta publication itself correctly left `latest=0.2.0`. After acceptance,
the user separately selected `0.3.0` and authorized one npm dist-tag mutation.
The authenticated command was:

```sh
printf '%s\n' '//registry.npmjs.org/:_authToken=${NPM_TOKEN}' |
secdat --dir /home/katsumata-m exec \
  --inject secret:only=NPM_TOKEN \
  --inject route:prefer=secret \
  --inject final:require=NPM_TOKEN \
  -- npm dist-tag add perttool@0.3.0 latest --userconfig=/dev/stdin
```

The durable post-promotion state is:

| Dist-tag | Version |
| --- | --- |
| `beta` | `0.3.0` |
| `latest` | `0.3.0` |
| `alpha` | `0.1.0-alpha.2` |

The first exact `npm i -g perttool` invocation reused a stale local npm
packument and left the existing global `perttool@0.2.0` in place even though
the registry's uncached `latest` endpoint already returned `0.3.0`. No second
dist-tag mutation was attempted. Repeating the same unqualified install with a
fresh verified npm cache installed `perttool@0.3.0`:

```sh
npm i -g perttool --prefer-online \
  --cache /tmp/perttool-npm-cache-0.3.0.zN7Rdu
perttool --version
npm ls -g perttool --depth=0
```

The installed binary at
`/home/katsumata-m/.nvm/versions/node/v25.1.0/bin/perttool` reported
`perttool 0.3.0`. This additional local smoke ran under Node.js 25.1.0; the
release baseline remains the already-passed Node.js 22 and 24 verification.
