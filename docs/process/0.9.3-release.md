## 1. Decision and scope

Select suffix-free `0.9.3` for the compatible Grammar 7 and CLI Contract 8
corrections accepted as ASSURE-002, ADV-004, and ADV-005. Installed users must
be able to inspect Grammar 7 assurance and advance either reported EOF receipt
topology without manually reordering source records or bypassing a guard.

The user's 2026-08-14 emergency instruction authorizes the ordered patch,
release, exact local installation, and completion of all three Issues after
every predecessor gate passes.

## 2. Fixed execution order

The dependency order is fixed by `plans/release-0.9.3.pert`:

1. `RELEASE_093_SELF_REVIEW` freezes compatibility, reproductions, and scope.
2. `RELEASE_093_CORRECTIONS` accepts the source and closed regression matrix.
3. `RELEASE_093_PREPARATION` aligns version-bearing source and passes complete
   local and static-analysis gates.
4. `RELEASE_093_CANDIDATE` accepts one clean commit and immutable tarball
   after read-only external preflight.
5. `RELEASE_093_PUBLISH` pushes the exact release commit and tag, requires
   Node.js 22 and 24 CI, creates one GitHub prerelease, and publishes the same
   tarball once to npm `beta`.
6. `RELEASE_093_ACCEPTANCE` independently verifies durable public identity,
   installed behavior, rollback, local exact installation, and Issue updates.

## 3. Candidate and mutation gates

Before the first external write:

1. require clean committed source identifying `0.9.3` in the package,
   lockfile, CLI, MCP server, and private adapter peer versions;
2. pass the complete Node.js 22 repository, static-analysis, documentation,
   self-use, private-adapter, temporary-link, and isolated-package gates;
3. establish that local and remote `v0.9.3`, its GitHub Release, and
   `perttool@0.9.3` are absent;
4. establish `beta=0.9.2`, `latest=0.9.0`, and no `alpha`;
5. freeze one tarball outside the worktree with its file count, sizes,
   SHA-256, integrity, and exact installed three-Issue behavior; and
6. stop if source, artifact, route, authorization, or external baseline
   changes.

The external mutation budget is one `main` push, one annotated-tag push, one
GitHub prerelease creation, one npm `beta` publication, and three Issue
completion updates. An ambiguous non-idempotent response is never retried
without readback. A later acceptance-record push, if used, targets the
original work-in-progress branch and remains outside the release commit.

## 4. Durable acceptance and remaining boundaries

Acceptance requires matching release commit and peeled tag, successful CI,
byte-identical retained, GitHub, and npm tarballs, registry integrity and
metadata, exact and beta isolated installations, the real three-Issue replay,
unchanged Contract 8 identities, and an exact `0.9.2` rollback installation.

Only after those facts are durable may local installations be updated to exact
`0.9.3` and Issues #14, #16, and #17 be closed with one evidence comment each
while retaining `bug` and removing `priority:P0`. npm `latest` remains
`0.9.0`. Plan advance remains separate.

## 5. Restart rules

- A source change after candidate acceptance invalidates the candidate.
- A changed registry, tag, Release, route, or CI baseline requires readback
  and reassessment before any write.
- A failed predecessor gate blocks every downstream operation.
- Publication is never retried solely because of short registry propagation;
  durable state is read first.
