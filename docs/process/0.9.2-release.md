## 1. Decision and scope

Select suffix-free `0.9.2` for the backward-compatible Grammar 7 and CLI
Contract 8 correction accepted as `ANALYSIS-001` and GitHub Issue #15. Valid
Point plans without velocity retain Point-valued scheduling and recommendation
facts, nullable velocity forecasts, and explicit temporal unavailability.

This is installed CLI behavior and the defect exists in released `0.9.1` and
its exact source. A repository-only correction would leave installed users
blocked. The user's 2026-08-14 emergency instruction explicitly authorizes the
ordered patch, release, exact local installation, and Issue completion after
all predecessor gates pass.

## 2. Fixed execution order

The dependency order is fixed by `plans/release-0.9.2.pert`:

1. `RELEASE_092_SELF_REVIEW` fixes compatibility, baseline, and release scope.
2. `RELEASE_092_CORRECTION` accepts the focused source and regression matrix.
3. `RELEASE_092_PREPARATION` aligns version-bearing source and passes the
   complete local gates.
4. `RELEASE_092_CANDIDATE` accepts one clean commit and immutable tarball
   after read-only external preflight.
5. `RELEASE_092_PUBLISH` pushes the exact release commit and tag, requires
   Node.js 22 and 24 CI, creates one GitHub prerelease, and publishes the same
   tarball once to npm `beta`.
6. `RELEASE_092_ACCEPTANCE` independently verifies durable public identity,
   installed behavior, rollback, local exact installation, and Issue #15.

## 3. Candidate and mutation gates

Before the first external write:

1. require clean committed source identifying `0.9.2` in the package,
   lockfile, CLI, MCP server, and private adapter peer versions;
2. pass the complete Node.js 22 repository, documentation, self-use, private
   adapter, temporary-link, and isolated public-package gates;
3. establish that local and remote `v0.9.2`, the GitHub Release, and
   `perttool@0.9.2` are absent;
4. establish `beta=0.9.1`, `latest=0.9.0`, and no `alpha`;
5. freeze one tarball outside the worktree with its file count, sizes, SHA-256,
   integrity, and exact installed Issue #15 behavior; and
6. stop if source, artifact, route, authorization, or external baseline
   changes.

The external mutation budget is one `main` push, one annotated-tag push, one
GitHub prerelease creation, one npm `beta` publication, and one Issue #15
completion update. An ambiguous non-idempotent response is never retried
without readback. A final acceptance-record push, if used, must target a
separate work-in-progress branch and remains outside the release commit.

## 4. Durable acceptance and remaining boundaries

Acceptance requires matching release commit and peeled tag, successful CI,
byte-identical retained, GitHub, and npm tarballs, registry integrity and
metadata, exact and beta isolated installations, the real Issue #15 matrix,
unchanged Contract 8 identities, and an exact `0.9.1` rollback installation.

Only after those facts are durable may the active local Node.js installations
be updated to exact `0.9.2`, and Issue #15 be closed with one evidence comment
while retaining `bug` and removing `priority:P0`. npm `latest` must remain
`0.9.0`. Plan advance remains separate.

## 5. Restart rules

- A source change after candidate acceptance invalidates the candidate.
- A changed registry, tag, Release, route, or CI baseline requires readback
  and reassessment before any write.
- A failed predecessor gate blocks every downstream operation.
- Publication is never retried solely because of short registry propagation;
  durable state is read first.
