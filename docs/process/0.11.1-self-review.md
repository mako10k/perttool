## 1. Decision

Select suffix-free `0.11.1` as the compatible patch after immutable `0.11.0`.
The patch carries the accepted correction that removes the second external VS
Code extension-inventory process from the supported-host gate and reads the
CLI-written profile registry directly after install and uninstall. It also
retains the corrected release evidence that distinguishes the observed host
timeout from an unproved VS Code internal cause.

The correction changes repository validation and evidence, not installed
perttool semantics. Grammar 9, CLI Contract 10, 71 commands, 29 active root
schemas, 139 root and Node exports, 51 Core exports, result identities,
governance, persistence, and Planning Pool behavior remain unchanged. The
public package includes only `dist`, `schemas`, and `CHANGELOG.md`; private
adapter and repository test sources remain excluded.

`0.11.1` is the smallest truthful immutable release version. Reusing `0.11.0`
would rewrite published identity, while `0.12.0` would overstate an unchanged
public contract.

## 2. Evidence

- The exact diff from peeled `v0.11.0` through `5197da8` changes the VSIX host
  harness, regression tests, and release/documentation records, with no change
  under public runtime source or schemas.
- The clean integrated commit is the remote `main` head and passed Node.js 22
  and 24 in run `34190654050`, including the root, LSP, VSIX, MCP, temporary

- Fresh reads found no local or remote `v0.11.1`, no GitHub Release for that

  `latest=0.10.5`, and no `alpha`.

## 3. Release boundary

Preparation may align version-bearing source and run local validation. One
later clean commit and one immutable tarball form the candidate. Git tag,
GitHub prerelease, and npm publication require confirmation bound to that exact
candidate. Publication moves only npm `beta`; `latest`, public VSIX
publication, Issue mutation, and plan advance remain separate.
