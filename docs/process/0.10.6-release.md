## Decision and scope

Select suffix-free `0.10.6` as a compatible patch after published `0.10.5`.
The release corrects milestone-acceptance criterion-set and receipt mutations
that ignore a valid canonical bracketed `dag_delegates` declaration.

The correction removes the independent regular-expression interpretation in
`src/milestone-acceptance/mutation.ts`. Every acceptance mutation must consume
the canonical validated pre-change effective governance metadata already owned
by the governance source contract. Candidate metadata must not self-authorize
the same mutation.

Grammar 8, CLI Contract 9, 56 commands, 23 root schemas, 129 root and Node
runtime exports, 45 Core exports, result identities, mutation candidates,
expected-digest checks, and safe persistence remain unchanged.

## Correction gate

The correction must establish all of the following from the exact base.

1. Reproduce Issue #36 for criterion replacement and receipt mutation before
   changing source.
2. Cover canonical absent, empty, one-item, and multiple-item delegate values.
3. For `dag_delegates [codex]`, make `codex` directly authorized for criterion
   replacement and every receipt action: `verify`, `fail`, `unavailable`,
   `revoke`, and `waive`.
4. Retain direct owner authority and fail closed for a missing actor,
   non-delegate actor, wrong actor, or malformed source.
5. Preserve preview, in-place write, expected-digest, candidate validation,
   source-race, symlink, and installed-package behavior.
6. Commit the correction and focused regression coverage without version,
   CHANGELOG, README, release-plan, or publication-record changes, so that the
   exact correction commit can later be applied independently to the preserved
   `0.11` workstream.

## Candidate gate

After the correction-only commit, align every version-bearing surface to
`0.10.6`. Pass the complete Node.js 22 repository gate, static ratchets,
English and documentation checks, all self-use plans, private LSP, MCP, and
VSIX gates, temporary linking, and isolated public-package installation.

Freeze one clean source commit and one tarball outside the worktree. Before
external mutation, prove that `perttool@0.10.6`, remote tag `v0.10.6`, and the
matching GitHub Release are unused; record npm `beta` and `latest`; verify the
authenticated Git, GitHub, and npm routes without exposing credentials; and
independently review the exact source commit and tarball.

Because `origin/main` contains separately preserved `0.11.0` work, publish the
old-version candidate through the explicit
`codex/hotfix-0.10.6-issue-36` remote branch gate from ADR 0003. Bind the
approved candidate to the exact preflighted `origin/main` commit; do not
rewrite main or include future-work bytes in `0.10.6`.

## Publication and acceptance gate

Publication requires a separate exact-candidate authorization after the
immutable source commit, tarball SHA-256, file count, byte size, and bounded
external write manifest are known.

Push the exact commit and annotated tag, require Node.js 22 and 24 hosted CI,
create one GitHub prerelease with the retained tarball and `SHA256SUMS`, and
publish the identical tarball exactly once to npm `beta`. Do not retry an
ambiguous external write before durable readback.

Independently read back Git, hosted CI, GitHub, npm, artifact identity, exact
and `beta` installations, the full Issue #36 authority matrix, and the exact
`0.10.5` rollback pin. Install exact `perttool@0.10.6` in the authorized local
user environment only after durable registry acceptance.

npm `latest`, Issue mutation, public VSIX publication, release-plan advance,
and integration into `codex/planning-pool-0.11-wip` remain separate.
