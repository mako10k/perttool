# perttool 0.10.6 release acceptance

Date: 2026-08-28

## Decision

The exact `perttool@0.10.6` candidate is durably accepted on the npm `beta`
channel. The release is a compatible Grammar 8 and CLI Contract 9 correction
for Issue #36. npm `latest` remains `0.10.5`.

The accepted source commit is
`fca015114a6d2ccd558a843c000e3fabd1ecb6e2`. The correction-only commit is
`56b7142fe4a6dbffa43847d73ba75854a4c696d2`; it remains independently
applicable to the preserved 0.11 workstream.

## Cause and controls

- Root cause: `src/milestone-acceptance/mutation.ts` independently interpreted
  governance text with a regular expression that did not accept the canonical
  bracketed `dag_delegates [codex]` form. This produced an empty effective
  delegate set and denied a valid delegate with `PTGOV-101`.
- Contributing cause: milestone-acceptance mutation maintained a second
  governance interpretation path instead of consuming the canonical validated
  governance projection.
- Escape and detection cause: the prior acceptance set covered owner
  confirmation but did not exercise absent, empty, one-item, and multiple-item
  bracketed delegates across criterion replacement, every receipt action, and
  CLI digest-bound persistence.
- Corrective action: the mutation path now uses
  `milestoneAcceptanceBaseText`, `validateTargetGrammar6Document`, and
  `governanceMetadataFromDocument`, and fails closed with `PTMAC-103` when the
  canonical projection is unavailable.
- Recurrence prevention: the fixed I36-001 through I36-018 matrix covers owner,
  delegate, non-delegate, missing and wrong actors, criterion replacement,
  verify, fail, unavailable, waive, revoke, preview, stale digest, write, and
  installed-package behavior.

This corrects the defect-producing interpretation mechanism rather than only
adding detection. Installed exact and beta replays prove that declared
delegates are accepted while the existing denial and safe-write boundaries
remain fail closed.
