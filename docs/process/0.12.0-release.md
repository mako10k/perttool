## Release gates

1. `RELEASE_0120_SELF_REVIEW`: confirm the owner-selected version, accepted
   scope, migration, exact public catalogs and previous-package boundary.
2. `RELEASE_0120_PREPARATION`: align current source and peer versions,
   current-version tests and derived goldens; pass the complete local and
   isolated-package workflow. Keep published-channel facts time-bound.
3. `RELEASE_0120_CANDIDATE`: after the required Git authorization, freeze
   clean committed source and retain one tarball outside the worktree with
   exact inventory, sizes, SHA-1, SHA-256 and npm integrity. Verify unused
   external identities, authenticated routes and exact installed behavior.
4. `RELEASE_0120_PUBLISH`: consume only the separately confirmed candidate
   commit, artifact and external payload; require Node.js 22/24 hosted CI,
   one GitHub prerelease and one publication of identical bytes to npm beta.
5. `RELEASE_0120_ACCEPTANCE`: independently verify Git, CI, GitHub, npm,
   byte identity, exact/beta installations and the prior exact rollback pin.

No ambiguous external write is retried before independent readback.
The confirmed [MCP incident judgment](mcp-discovery-timeout-rca-2026-09-30.md)
allows proceeding after a passing rerun without complete attribution of the
original timeout. It does not exempt other gate failures. The owner subsequently adopted the discovery-only test budget adjustment
from 5000 to 15000 ms; its focused and complete gates passed. Product runtime
deadlines and CI concurrency remain unchanged.

npm latest promotion, Issue writes, public VSIX publication, feature/release
plan advance and milestone receipts are separate owner-controlled actions.
No remote availability or publication is established by this local procedure.
