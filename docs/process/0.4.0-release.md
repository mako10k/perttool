## 1. Decision and scope

Select suffix-free `0.4.0` for the first package that publishes accepted
Grammar 4, owner-aware goal and DAG mutation governance, and CLI Contract 5.
The grammar, command options, JSON envelopes, result schemas, and persistent
write authority change together. `0.3.1` would understate that compatibility
boundary, while `1.0.0` remains reserved for a future stable-series decision.

The completed governance plan and its acceptance record remain the
implementation authority. This release plan does not restore or duplicate
their completed task state. `RELEASE_040_CONTRACT_5_READINESS` verifies the
reached governance finish and accepted source/package boundary before
release-source preparation begins.

This release includes:

- Grammar 4 declared and effective owner/delegate metadata;
- owner-aware direct, batch, and advance planning and persistence;
- `Perttool.ProjectResult.v3`, `Perttool.MutationResult.v2`, and
  `Perttool.GovernanceDecision.v1`;
- CLI Contract 5 dispatch, options, help, Guide, diagnostics, warnings, and
  installed file-first workflows;
- retained Grammar 1/2/3 compatibility through effective default ownership;
- the Contract 4 temporal, deadline, exact unit-migration, and NextResult v4
  behavior already published in `0.3.0`; and
- other accepted changes recorded under `CHANGELOG.md`'s Unreleased section
  when release source is prepared.

This gate does not:

- publish a partial governance surface or a second `0.3.0` artifact;
- promote `0.4.0` to npm `latest`;
- close Issue #4;
- declare stable product maturity or select `1.0.0`;
- add authentication, verified identity, signatures, durable approval audit,
  technical prevention of direct editing, recommendation override apply,
  MIG-08, Git integration, Issue #3, LSP, VSIX, MCP, or runtime i18n; or
- absorb the independent English-baseline workstream.

## 9. Restart and rollback

- Before any external write, correct source or tests and rerun the candidate
  gate.
- If authorization is absent, retain `RELEASE_040_PUBLISH` as blocked; do not
  infer authority from the plan, an earlier unrelated PUBLISH, or local
  acceptance.
- After pushing only the release commit, inspect `origin/main` and resume from
  tag creation; do not create a second release commit silently.
- Never rewrite a published annotated tag. If tagged source is wrong, stop
  and select a new version through a new release decision.
- After creating a GitHub release or publishing to npm, inspect durable state
  before retrying. npm versions and published release artifacts are
  immutable; fix forward with a new version rather than unpublish.
- If npm publication succeeds but immediate reads return propagation-time
  `E404`, use the bounded verification in `scripts/publish-npm.sh`; do not
  publish again.
- If `latest` changes unexpectedly, stop. Do not perform a compensating
  dist-tag mutation without separate explicit authorization.

Rollback for consumers means pinning `perttool@0.3.0` while a separately
reviewed Contract 5 fix is prepared. Runtime aliases are not restored.
