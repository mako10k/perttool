## 1. Decision and scope

Select suffix-free `0.5.3` for the compatible CLI Contract 6 and Grammar 5
patch that publishes:

- the maintained beta-only npm publication guard after retirement of the
  obsolete alpha dist-tag;
- assertion-free first previews and omission of loose owner assertions from
  not-applicable maintenance;
- one-candidate, explicitly affected-scope confirmation without carryover to
  later commands or `dag advance`; and
- human-readable modification time, before/after size, diff counts, and
  semantic change context before supplemental machine digests.

The patch retains Grammar 5, CLI Contract 6, all 34 commands, all option
spellings, runtime and schema identities, payload meanings, stable exits,
safe-write controls, and package-root values. It does not create Contract 7,
Grammar 6, a new result field, strict authentication, an accepted-scope
option, or an npm `latest` promotion.

## 2. Work packages and authority

The dependency order is fixed by `plans/release-0.5.3.pert`.

1. `RELEASE_053_SELF_REVIEW` verifies the threat model, compatibility,
   human-readable confirmation context, tests, and release safety.
2. `RELEASE_053_PREPARATION` aligns version-bearing source, release
   documentation, self-use checks, tests, and goldens.
3. `RELEASE_053_CANDIDATE` accepts one clean commit and one immutable tarball
   after complete local and read-only external preflight.
4. `RELEASE_053_PUBLISH` pushes the release commit and annotated tag, creates
   the GitHub prerelease, and publishes the same tarball once to npm `beta`.
5. `RELEASE_053_ACCEPTANCE` records durable identity and public-channel
   verification.

The user's 2026-07-30 release instruction authorizes this complete named
sequence once every predecessor gate passes and no blocking finding remains.
It does not authorize npm `latest` promotion or a different version, tag,
artifact, or publication channel.

## 4. Candidate gate

Before the first external write:

1. require clean committed source with package, lockfile, CLI version, and
   intended tag equal to `0.5.3` and `v0.5.3`;
2. pass the complete repository and isolated-package gates under Node.js 22;
3. reconfirm that local/remote `v0.5.3`, the GitHub Release, and
   `perttool@0.5.3` are absent;
4. record current npm `beta` and `latest` and confirm `alpha` remains absent;
5. verify protected Git, GitHub, and process-scoped npm routes without
   displaying credentials;
6. build one tarball outside the worktree, record its size and digests, and
   retain it unchanged; and
7. stop if source, artifact, authorization, or external baseline changes.

The release commit is the commit that records candidate acceptance. Because
repository-only records are excluded from the package, later durable records
must not regenerate or replace the accepted tarball.

## 6. Durable acceptance

Acceptance requires:

- local, remote-main, release commit, and peeled tag identity;
- byte-identical candidate, GitHub, and npm tarballs;
- registry integrity, metadata, `beta=0.5.3`, unchanged `latest=0.5.1`, and
  absent `alpha`;
- successful isolated installation from both public channels;
- `--version`, Contract 6 help and Guide, Grammar 5 checking, governance,
  schema lookup, package-root lookup, and beta-only publication guard;
- successful candidate CI on Node.js 22 and 24; and
- exact commands, outputs, URLs, digests, and propagation observations in
  separate PUBLISH and acceptance records.

The accepted artifact is immutable. Durable records and residual plan
advances occur in later commits and do not change the release tarball.
