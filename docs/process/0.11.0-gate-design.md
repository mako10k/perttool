  executable set. Before gate acceptance, the result must make one current

  recommendation. The `priority:P1` label and PERT correction task are now
  registered; correction and acceptance remain open.

truthful target version, but neither its gate nor source preparation may be
accepted until both P1 findings are corrected and independently accepted, or
the owner explicitly changes their priority and accepts a bounded deferral.

## 5. Root-cause and escape boundary

The Issue #36 root cause was the milestone-acceptance mutation layer's second,
regex-based interpretation of `dag_delegates`, which diverged from the
canonical validated governance model for bracketed lists. The integrated
source removes that duplicate interpretation and reuses the canonical model.
The focused regression is recurrence prevention and escape containment; it is
not presented as the source-cause correction.

The Candidate 1.0 composition defect had a different root cause: Contract 10
added the Planning Pool grammar layer, but `runMilestoneAcceptance` still
composed only through the Contract 9 temporal layer. A valid Grammar 9 source
therefore reached a planner whose accepted input ended at the older grammar
instead of being projected to that input and lifted back. The missing Grammar
9 by milestone-acceptance cross-case explains escape; it did not create the
incorrect composition.

Candidate 1.1 then introduced a separate correction defect. Its outer lift
assumed the lowered and updated documents differed in one continuous range.
When an acceptance record was before a masked Planning Pool declaration, that
range included both the owned acceptance edit and unrelated Pool bytes. The
result stayed syntactically valid, so final validation did not expose the data
loss. Candidate 1.2 removes that assumption by carrying normalized owned edits
and failing closed if an edit touches any lowered source line. The placement
matrix and reordered installed-package replay address the escape boundary.

Candidate 1.2 retained one further conflation: `ok=false` meant both “no valid
candidate” and “a valid candidate exists but persistence authority is denied.”
The early return therefore exposed the lowered Grammar 7 candidate for an
unauthorized Grammar 9 write, even though the source file remained unchanged.
Candidate 1.3 uses candidate presence as the lift condition, preserves
`PTGOV-101` and `written=false` independently, and adds CLI plus installed-
package denial replay with exact candidate reconstruction.

The governance-binding finding has a separate root cause: the Grammar 7
candidate lift replaces outer source and candidate digests after planning on a
lowered Grammar 6 document but preserves the planner's nested governance
object. The Grammar 8 and 9 generic lifts retain the same broad-spread
assumption. Tests asserted outer governance binding on the specialized Grammar
9 milestone-acceptance correction, but did not cross the generic assurance-
mutation path over all three grammar layers; that is the escape cause.

Issue #37 also has a separate root cause: recommendation ranking and resource-
schedule selection independently consume the same ready set and capacity, then
publish their selections in one result without a final reconciliation rule.
Subsystem tests explain each selection but did not require the recommended set
to agree with `runnable_now`, which is the escape cause.
