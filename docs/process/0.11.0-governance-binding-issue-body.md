## Summary

An assurance mutation against a valid Grammar 7 document reports the outer
document's digest in `source_digest` and `original_digest`, but retains the
lowered Grammar 6 digest in the nested
`Perttool.GovernanceDecision.v2.source_digest`.

The decision therefore claims to authorize or deny a different source byte
sequence from the one identified by the enclosing mutation result.

## Environment

Reproduced with both:

- published `perttool 0.10.6`, CLI Contract 9;
- the current unreleased CLI Contract 10 line;
- Grammar 7 input;
- `Perttool.MutationResult.v6`; and
- `Perttool.GovernanceDecision.v2`.

## Reproduction

From a perttool source checkout containing `plans/editor-mutations.pert`, run:

```bash
perttool task-outcome add \
  plans/editor-mutations.pert \
  OUTCOME_GATE_BINDING_PROBE \
  EDITOR_REPAIR_ACCEPTANCE \
  --status conformant \
  --reason "Probe lifted governance source binding" \
  --actor codex \
  --format json
```

The command is a preview. It does not include an owner assertion and does not
write the plan.

## Observed behavior

Both the published and current CLIs return:

```json
{
  "schema_version": "Perttool.MutationResult.v6",
  "operation": "task-outcome.add",
  "ok": true,
  "changed": true,
  "source_digest": "sha256:bb9fd570b828c0dd9643e2739434d9963ea4c202710eed685a2d16115704d3b4",
  "original_digest": "sha256:bb9fd570b828c0dd9643e2739434d9963ea4c202710eed685a2d16115704d3b4",
  "governance": {
    "schema_version": "Perttool.GovernanceDecision.v2",
    "source_digest": "sha256:605086578642142ced6d8b1d8737676c87d2424fb78cf9e9e3f17d8d63681dfe",
    "applicable": true,
    "required_owner_confirmations": ["user"],
    "owner_confirmation_required": true,
    "write_authorized": false
  },
  "write": {
    "mode": "preview",
    "target": null,
    "written": false
  }
}
```

The outer digest is the SHA-256 of the actual Grammar 7 input. The nested
digest is the SHA-256 of the Grammar 6 text produced after milestone-
acceptance declarations are removed for the older planner.

## Expected behavior

Every authority-bearing object in a lifted result must identify the same
authoritative outer source as the enclosing mutation result. For this case:

```text
source_digest == original_digest == governance.source_digest
```

The same invariant must hold for generic assurance mutations lifted through
Grammar 7, 8, and 9, including authorized and denied preview, separate-output,
and in-place paths. Candidate bytes, candidate digest, affected scopes,
effective owners, delegates, denial causes, and safe-write behavior must remain
unchanged apart from correcting the false source binding.

## Root cause

The Grammar 7 candidate lift plans against a lowered Grammar 6 document and
then replaces the enclosing original and candidate digests after lifting the
edits back to the outer source. It broadly spreads the older planner result and
therefore preserves its nested governance decision without rebinding that
decision to the outer source. The generic Grammar 8 and Grammar 9 candidate
lifts retain the same nested object through another broad spread.

The defect escaped because tests covered outer candidate identity and the
specialized Grammar 9 milestone-acceptance mutation path, but did not assert
the nested governance binding for generic assurance mutations across all three
lifted grammar layers.

## Severity

P1. This is a false public audit and authority binding and blocks a release
claim that digest-bound governance is preserved. The current evidence does not
show a P0 write-authority bypass: persistence still checks the outer
`original_digest`, the candidate digest, the governance authorization result,
and the target immediately before replacement.

## Acceptance criteria

- Rebind the complete nested governance decision to the authoritative outer
  source for generic assurance mutations on Grammar 7, 8, and 9.
- Assert outer `source_digest`, `original_digest`, and nested
  `governance.source_digest` equality for changed, denied, no-op, and invalid
  results wherever governance is present.
- Preserve candidate bytes, candidate digest, normalized edits, affected
  scopes, effective owners and delegates, required confirmations, denial
  causes, and result schema identity.
- Retain missing-owner, wrong-owner, stale expected-digest, candidate-digest,
  validation, and atomic-write failure behavior without weakening a guard.
- Cover Core, public CLI JSON, installed-package schema validation, preview,
  separate output, and in-place write paths.
- Reproduce the command above before the correction and prove equal outer and
  nested source bindings after it.

## Non-goals

- Do not change the project's governance owners, delegates, or affected-scope
  classification.
- Do not treat an owner assertion as persistent authority or reuse it across
  candidates.
- Do not change Grammar or CLI Contract identities solely for this correction.
- Do not republish or overwrite `0.10.6`; release and backport selection remain
  separate decisions.
