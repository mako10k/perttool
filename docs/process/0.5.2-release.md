## 1. Decision and scope

Select suffix-free `0.5.2` for the compatible CLI Contract 6 and Grammar 5
patch that publishes:

- concrete closed definitions for every nested result record;
- typed value schemas for intentionally extensible maps;
- explicit `full` and reference-based `outline` schema views;
- separate bundled `$ref` detail selection; and
- installed CLI and package-root verification of those views.

The patch retains Grammar 5, CLI Contract 6, all existing commands, runtime
result identities and payload meanings, stable exits, the default complete
schema lookup mode and original query projection, and all existing runtime
package-root values. It does not create Contract 7, Grammar 6, new runtime
result identities, a stable series, or an npm `latest` promotion.

## 2. Work packages and authority

The dependency order is fixed by `plans/release-0.5.2.pert`.

1. `RELEASE_052_SELF_REVIEW` verifies the complete schema correction,
   compatibility, outline boundary, tests, and release safety.
2. `RELEASE_052_PREPARATION` aligns version-bearing source, release
   documentation, self-use checks, tests, and goldens.
3. `RELEASE_052_CANDIDATE` accepts one clean commit and one immutable
   tarball after complete local and read-only external preflight.
4. `RELEASE_052_PUBLISH` pushes the release commit and annotated tag, creates
   the GitHub prerelease, and publishes the same tarball once to npm `beta`.
5. `RELEASE_052_ACCEPTANCE` records durable identity and public-channel
   verification.

The user's 2026-07-30 instruction authorizes this complete named sequence once
every predecessor gate passes and no blocking finding remains. It does not
authorize npm `latest` promotion or a different version, tag, artifact, or
publication channel.

## 3. Source-preparation gate

Update and verify together:

- `package.json`, root lockfile entries, and `src/version.ts`;
- a dated `0.5.2` CHANGELOG section and comparison link;
- README current-channel and full/outline/detail guidance;
- ADR, requirements, design, release procedure, self-use registry, plan
  goldens, and release tests;
- package inclusion, CLI/API parity, strict schema compilation, reference
  resolution, and publish normalization.

Run under Node.js 22:

```sh
npm ci
npm run check
git diff --check
```

No external write is allowed in this gate.

## 4. Candidate gate

Before the first external write:

1. require clean committed source with package, lockfile, CLI version, and
   intended tag equal to `0.5.2` and `v0.5.2`;
2. pass the complete repository and isolated-package gates under Node.js 22;
3. reconfirm that local/remote `v0.5.2`, the GitHub Release, and
   `perttool@0.5.2` are absent;
4. record current npm `beta`, `latest`, and `alpha`;
5. verify protected Git, GitHub, and process-scoped npm routes without
   displaying credentials;
6. build one tarball outside the worktree, record its size and digests, and
   retain it unchanged; and
7. stop if source, artifact, authorization, or external baseline changes.

The release commit is the commit that records candidate acceptance. Because
repository-only records are excluded from the package, later durable records
must not regenerate or replace the accepted tarball.
