## 1. Decision and scope

Select suffix-free `0.7.0` for the first package that publishes Grammar 6,
CLI Contract 7, and conditional plan assurance. The grammar, command registry,
result identities, governance interface, recommendation start authority,
advance semantics, schema catalog, package root, and installed workflow change
together. `0.6.1` would understate this breaking public boundary, while
`1.0.0` remains reserved for a future stable-series decision.

The completed `ASSURE-001` plan and its accepted records remain the
implementation authority. This release plan does not restore or duplicate
their completed task state. `RELEASE_070_CONTRACT_7_READINESS` verifies the
complete pre-advance workstream and accepted source/package boundary before
release-source preparation begins. Canonical advance of either plan is not a
release prerequisite and remains a separate mutation.

This release includes:

- Grammar 6 assurance declarations, default `both`, explicit
  `planning_only` and `execution_only` relations, component seals, outcome
  commitments, and frontier receipts;
- CLI Contract 7 with 44 commands, `plan-assurance show`, scalar
  `plan-assurance hash`, preview-first seal/reseal/outcome/relation mutations,
  and complete help and Guide projections;
- `Perttool.PlanAssuranceResult.v1`, `Perttool.CheckResult.v4`,
  `Perttool.ProjectResult.v4`, `Perttool.AnalysisResult.v5`,
  `Perttool.NextResult.v6`, `Perttool.MutationResult.v4`, and
  `Perttool.AdvanceResult.v2`;
- `Perttool.GovernanceDecision.v2`, assurance impact, complete mismatch cause
  paths, required actions, and fail-closed new-start authority;
- assurance-preserving advance contraction with independently composed Git
  history safety and exact frontier-receipt reconstruction;
- Grammar 1 through 5 compatibility with assurance reported as not enabled;
- Grammar 6 compatibility across formatting, lifecycle, history, unit
  migration, atomic mutation, and Mermaid semantic profile 2; and
- 20 complete Draft 2020-12 root schemas, package-root APIs, temporary-link,
  and isolated installed-package coverage.

This gate does not:

- claim that SHA-256 is a digital signature, authenticated approval, malicious
  edit resistance, external transparency log, or root of trust;
- implement the opt-in archived advance backlog, REOPEN, MIG-08, human
  override apply, durable authorization audit, Issue synchronization, LSP,
  VSIX, MCP, or runtime i18n;
- promote `0.7.0` to npm `latest`;
- advance `plans/plan-assurance.pert` or this release plan;
- mutate an Issue; or
- declare stable product maturity or select `1.0.0`.

## 2. Work packages and authority

The dependency order is fixed by `plans/release-0.7.0.pert`:

1. `RELEASE_070_GATE_DESIGN` selects the version and fixes requirements, ADR,
   design, this procedure, the release plan, restart rules, current channel
   facts, and external authority boundaries.
2. `RELEASE_070_CONTRACT_7_READINESS` verifies complete ASSURE-001 acceptance,
   the active public source/package boundary, and the absence of hidden
   acceptance findings.
3. `RELEASE_070_PREPARATION` aligns version-bearing source, migration and
   release documentation, tests, goldens, audit state, and package validation.
4. `RELEASE_070_CANDIDATE` accepts one clean release commit and one immutable
   tarball after complete local and read-only external preflight.
5. `RELEASE_070_PUBLISH` pushes the release commit and annotated tag, waits
   for CI, creates the GitHub prerelease, and publishes the same tarball once
   to npm `beta`.
6. `RELEASE_070_ACCEPTANCE` independently records durable public identity and
   installed behavior without changing the immutable artifact.

## 7. Durable acceptance

Independently re-read the release commit, peeled tag, successful CI, GitHub
and npm metadata, common candidate/GitHub/npm bytes and digests, registry
integrity, and isolated public-package behavior. The record must prove the
exact Grammar 6, CLI Contract 7, plan-assurance, compatibility, hash,
authority, advance, help, Guide, schema, and package-root boundaries.

Do not move `latest`, advance either plan, or mutate an Issue during durable
acceptance.

## 8. Restart and rollback

- Before an external write, rebuild and reverify only from the current clean
  candidate commit and discard any replaced local candidate.
- For an ambiguous Git or GitHub mutation, read the exact remote reference or
  release asset before deciding whether a retry is necessary.
- For an ambiguous npm publication, read exact version, tarball, integrity,
  and dist-tags before any retry.
- If a public artifact differs from the accepted candidate, stop acceptance;
  never overwrite a tag, release asset, or immutable npm version.
- Consumers can roll back by pinning `perttool@0.6.0`. Do not repair a
  `0.7.0` problem by moving `latest` or republishing the same version.
