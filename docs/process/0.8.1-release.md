# `v0.8.1` Advance Receipt Overlap Beta Patch Release

- Status: Accepted 1.0
- Decision date: 2026-08-12
- Target version: `0.8.1`
- Product maturity: beta
- GitHub channel: prerelease
- npm publication tag: `beta`
- Issue: [#9](https://github.com/mako10k/perttool/issues/9)

## Decision and scope

Release suffix-free `0.8.1` as a backward-compatible Grammar 6 and CLI
Contract 7 patch. The correction places a newly created assurance frontier
receipt before an advance-owned terminal deletion suffix instead of inserting
it at EOF inside that deletion. It retains all 45 commands, 21 schemas, result
identities, payload meanings, public exports, governance, history-safety, and
plan-assurance authority.

The release excludes the separately developed Point-default and private VSIX
presentation changes. It is based on accepted `0.8.0` source plus the Issue #9
fix and release metadata only.

## Acceptance gates

1. Verify the minimal all-terminal-work-events reproduction and the retained
   consumer-event variant.
2. Verify byte-identical preview, `--out`, and `--write` candidates.
3. Pass the complete Node.js 22 repository, documentation, self-use, adapter,
   link, and isolated-package gates from a clean committed source.
4. Prove `v0.8.1`, its GitHub Release, and `perttool@0.8.1` are unused before
   publication and freeze one immutable tarball.
5. Push and read back the exact release commit and annotated tag, require CI,
   create one GitHub prerelease, publish the same tarball once to npm `beta`,
   then set `latest` to the accepted patch.
6. Install the public exact version locally and verify the CLI version and
   Issue #9 regression from installed bytes.

Ambiguous external mutations are never retried without readback. Plan advance,
public VSIX publication, and unrelated Issue mutation remain separate.
