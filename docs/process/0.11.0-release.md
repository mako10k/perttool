package. The release publishes Work, project-owned Event and Activity AoA,
global Work order, planning-only dependencies, audited reshape, guided intent
requests, projection and narrow deferral, active Windows, independent
observations, bounded first-parent history, eleven original Planning Pool
commands, four additive Event and Activity inspection commands, three Planning

The exact target surface is 71 commands, 29 active root schemas, 139 root and

`Perttool.UnitMigrationResult.v5` replace their Contract 9 predecessors.
Private LSP, VSIX, and MCP workspaces remain excluded from the npm tarball.

## 2. Compatibility and rollback

Grammar 1 through 8 remain readable for their supported operations. Planning
Pool mutation requires Grammar 9 and never migrates implicitly.
`document migrate --target-grammar 9` accepts valid Grammar 8, changes only the
version field and owned migration trivia, inserts no Planning Pool
declaration, and preserves the strict-DAG meaning.

Exact `perttool@0.10.6` is the rollback pin. It is the latest published
Contract 9 beta and includes the Issue #36 correction that makes milestone-
acceptance mutations consume canonical validated DAG governance metadata.
Rollback removes the Grammar 9 and Contract 10 surface; it is not a downgrade
route for a document already using Planning Pool declarations because no
automatic Grammar 9 to 8 migration exists.

## 4. Source-preparation gate

Preparation carries the correction-only Issue #36 commit already applied to
the preserved `0.11.0` line and retains the accepted `0.10.6` changelog and
release-policy history. It does not import `0.10.6` package identity,
generated version goldens, candidate tarball, or release-plan lifecycle state.
It also consumes the independently accepted Grammar 9 milestone-acceptance
composition correction; that correction is a prerequisite, not deferred
preparation work.

Preparation did not start while Issue #38 left generic assurance-mutation
governance bound to lowered source bytes or while Issue #37 permitted one
NextResult to recommend a task that it simultaneously marked non-runnable. The
release gate records both as P1 correction inputs. The current plan retains
independently accepted conformant Outcomes for both corrections and for Gate
Design. The owner separately accepted the exact selected Preparation reseal;
complete Next then made only Preparation startable, and the task started at
`2026-09-07T17:36:09+09:00`.

Preparation aligns `package.json`, both root lockfile entries, CLI and adapter
versions, MCP identity, CHANGELOG, README, migration and rollback guidance,
tests, goldens, self-use, and release records. It requires the complete Node.js
22 repository gate, private-adapter gates, supported-host VSIX gate, temporary
linking, and isolated-package workflow. It performs no remote or registry write
and retains no release tarball. Source Preparation Candidate 1.0 satisfies
those local conditions as recorded in
[`0.11.0-preparation.md`](0.11.0-preparation.md). The owner then accepted that
exact preparation, its finish and conformant Outcome were registered, and only
the separately resealed Candidate task became startable and started.

## 5. Candidate and publication boundaries

Candidate acceptance starts only from clean committed `0.11.0` source. It
rechecks that the local and remote `v0.11.0` tag, GitHub Release, and npm
version are unused; reads the then-current distribution tags; validates the
authenticated routes without exposing credentials; and retains one immutable
tarball outside the worktree with its exact source, size, file count, SHA-256,
integrity, and installed behavior.

Owner acceptance of gate design does not authorize preparation or any later
mutation. PUBLISH requires a later authorization naming that exact candidate
and external write batch. It pushes and verifies the release commit and
annotated tag, requires Node.js 22 and 24 CI, creates one GitHub prerelease and
SHA256SUMS, and publishes the identical tarball exactly once to npm `beta`
through the guarded credential route. Ambiguous writes are read back and are
never blindly retried.

## 6. Stopping points

Publication leaves npm `latest` unchanged. Durable acceptance, any later
`latest` promotion, public VSIX publication, Issue closure, Planning Pool plan
advance, release-plan advance, the interface-contract-aware affected-test
selector, and Issue #24 Goal Coverage and Goal Seal are separate decisions.
Gate design and source preparation do not perform an external write.
