## 1. Scope and compatibility

Publish the accepted VSIX supported-host harness correction as suffix-free
`0.11.1`. The corrected gate replaces a second potentially blocking VS Code
`--list-extensions` read with direct parsing of the profile-local
`extensions.json` written by the already completed install or uninstall
command. Process ownership, bounded termination, Xvfb execution, registry
validation, replacement, uninstall, and clean-profile guarantees remain.

The package retains Grammar 9, CLI Contract 10, 71 commands, 29 active root
schemas, 139 root and Node exports, 51 Core exports, and every public runtime
meaning. This patch does not claim that the unavailable upstream VS Code
internal boundary was identified; it removes perttool's causal dependence on
that second process.

## 2. Dependency order

1. `RELEASE_0111_SELF_REVIEW` fixes the compatibility judgment and release
   boundary against the integrated source and fresh external state.
2. `RELEASE_0111_PREPARATION` aligns every version-bearing surface and passes
   the complete local, adapter, Xvfb VSIX, temporary-link, self-use, and
   isolated-package gates without publishing.
3. `RELEASE_0111_CANDIDATE` commits clean source, proves unused external
   identities and protected routes, and retains one immutable tarball.
4. `RELEASE_0111_PUBLISH` consumes only an exactly confirmed candidate, pushes
   the release commit and annotated tag, requires Node.js 22 and 24 CI, creates
   one GitHub prerelease, and publishes the same tarball once to npm `beta`.
5. `RELEASE_0111_ACCEPTANCE` independently verifies durable Git, CI, GitHub,
   npm, artifact, exact and beta installation, correction, and rollback facts.

## 3. Candidate and publication gates

The candidate gate requires a clean committed checkout, a complete Node.js 22
gate, an immutable tarball outside the worktree, exact file count, packed and
unpacked sizes, SHA-1, SHA-256 and npm integrity, installed Contract 10
behavior, unused `v0.11.1` GitHub and npm identities, and credential-route dry
runs without secret disclosure.

External publication starts only after confirmation naming the exact candidate
commit and SHA-256. Do not retry an ambiguous tag, GitHub Release, or npm write.
Read back the external object first and resume only a demonstrably missing
step. The npm publication operation must leave `latest=0.10.5` and absent
`alpha` unchanged.

## 4. Remaining boundaries

npm `latest` promotion, public VSIX publication, Issue mutation, this release
plan's advance, the retained `0.11.0` plans' advance, and unrelated backlog
work are not part of this release.
