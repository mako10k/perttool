## 1. Observed failure

Manual run `34113325516` attempt 1 passed Node.js 22. Its Node.js 24 job passed
1,341 tests, English and documentation checks, 46-plan self-use, and isolated
LSP and MCP gates. After downloading VS Code 1.101.0, the first
`code --list-extensions --show-versions` read exceeded the harness's
120-second timeout under Xvfb. Attempt 2 reran the failed Node.js 24 job and
passed against the unchanged release commit. Main push run `34115992442` then
passed Node.js 22 and 24 against the same commit.

Accepted `0.9.2`, `0.10.0`, and `0.10.5` release records show the same
extension-inventory timeout followed by a successful bounded failed-job rerun.
The recurrence is therefore a repository test-harness condition, not evidence
of a Planning Pool source or immutable-candidate difference.

## 2. Causal classification

- Root cause of the CI failure: the supported-host harness treated one timeout
  from the recurrent external read-only extension-inventory process as a
  terminal source-check result. It had no timeout-specific retry boundary.
- Remaining unknown: available evidence does not establish why the external
  VS Code 1.101.0 process sometimes failed to terminate. The old timeout path
  discarded captured stdout and stderr, and the unchanged command later
  passed.
- Contributing causes: the generic runner signaled only its direct child,
  rejected before process closure, and omitted captured output from the error.
- Escape cause: prior releases used whole-job reruns without correcting the
  recurring harness mechanism. The `0.11.0` release regression asserted only
  the successful attempt-2 wording and did not require the failed attempt to
  remain visible.

## 3. Corrective and recurrence-prevention changes

`scripts/check-vsix-host.mjs` now:

- reports a typed timeout with the command, timeout, stdout, and stderr;
- terminates the POSIX subprocess group and waits for close before returning
  the timeout;
- retries only `--list-extensions --show-versions`, only after a typed timeout,
  and at most once; and
- fails immediately for any ordinary nonzero exit and fails closed after a
  second timeout.

Executable regression tests prove captured timeout diagnostics, one retry
after process closure, and no retry for an ordinary process failure. Release
regression checks now require the exact attempt-1 failure, attempt-2 recovery,
unchanged candidate identity, current plan index, and current agent guidance.
