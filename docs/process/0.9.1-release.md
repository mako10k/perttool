## 1. Decision and scope

Select suffix-free `0.9.1` for the backward-compatible Grammar 7 and CLI
Contract 8 correction accepted as `ACT-003` and GitHub Issue #8. The active
`project observe-velocity` command now binds declared evidence to the exact
current operand and keeps Git-recorded evidence bound to the selected
first-parent revision. The `all` selector projects both evidence classes
without substituting the committed source for the current declared source.

This is distributed CLI behavior, so leaving the correction only in the
repository would not repair the documented `task finish` followed by
`project observe-velocity` workflow for installed consumers. `0.9.1`
accurately identifies a compatible correction. A new minor would overstate
the boundary.

The patch retains Grammar 7, CLI Contract 8, all 53 commands, all 23 root
schemas, all 129 reference-identical root and Node exports, all 45 portable
Core exports, command and option spellings, result and schema identities,
payload structure, governance, safe-write behavior, milestone acceptance,
and recommendation authority. It does not automatically adopt observed
velocity or change `project history`.

## 2. Fixed execution order

The dependency order is fixed by `plans/release-0.9.1.pert`:

1. `RELEASE_091_SELF_REVIEW` fixes the compatibility and release boundary.
2. `RELEASE_091_PREPARATION` aligns version-bearing source and passes the
   complete local gates.
3. `RELEASE_091_CANDIDATE` accepts one clean commit and one immutable tarball
   after read-only external preflight.
4. `RELEASE_091_PUBLISH` pushes the exact release commit and tag, requires
   Node.js 22 and 24 CI, creates one GitHub prerelease, and publishes the same
   tarball once to npm `beta`.
5. `RELEASE_091_ACCEPTANCE` independently verifies durable public identity,
   installed behavior, and rollback, then updates Issue #8.

The user's 2026-08-13 instruction explicitly authorizes this plan, push,
Issue #8 update, and release subject to the predecessor gates. It does not
authorize npm `latest` promotion, release-plan advance, public VSIX
publication, or unrelated Issue mutation.

## 3. Candidate and mutation gates

Before the first external write:

1. require clean committed source identifying `0.9.1` in the package,
   lockfile, CLI, and private adapter peer versions;
2. pass the complete Node.js 22 repository, documentation, self-use, private
   adapter, temporary-link, and isolated public-package gates;
3. establish that local and remote `v0.9.1`, the GitHub Release, and
   `perttool@0.9.1` are absent;
4. establish `beta=latest=0.9.0` with no `alpha`;
5. freeze one tarball outside the worktree with its file count, sizes,
   digests, integrity, and installed behavior; and
6. stop if source, artifact, route, authorization, or external baseline
   changes.

The authorized external mutation budget is one branch push, one `main` push,
one annotated-tag push, one GitHub prerelease creation, one npm `beta`
publication, and one Issue #8 completion update. A final acceptance-record
push may move only the existing work-in-progress branch. An ambiguous
non-idempotent response is never retried without readback.

## 4. Durable acceptance and remaining boundaries

Acceptance requires matching release commit and peeled tag, successful CI,
byte-identical retained, GitHub, and npm tarballs, registry integrity and
metadata, exact and beta isolated installations, the real Issue #8
uncommitted-finish regression, unchanged Contract 8 identities, and an exact
`0.9.0` rollback installation.

Only after those facts are durable may Issue #8 be closed with one evidence
comment while retaining the `bug` label and removing its delivery-priority
label. npm `latest` must remain `0.9.0`. Plan advance remains separate.

## 5. Restart rules

- A source change after candidate acceptance invalidates the candidate.
- A changed registry, tag, Release, route, or CI baseline requires readback
  and reassessment before any write.
- A failed predecessor gate blocks every downstream operation.
- Publication is never retried solely because of a short registry propagation
  failure; durable state is read first.
