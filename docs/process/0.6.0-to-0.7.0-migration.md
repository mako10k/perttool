# `0.6.0` to `0.7.0` Conditional Plan Assurance Migration

- Status: Accepted 1.0
- Source package: `perttool@0.6.0`
- Target package: `perttool@0.7.0`
- Source grammar and CLI: Grammar 5, CLI Contract 6
- Target grammar and CLI: Grammar 6, CLI Contract 7
- Target feature: conditional plan assurance model 1

## 1. Why the package minor changes

Version `0.7.0` publishes one atomic boundary for Grammar 6 conditional plan
assurance, ten assurance commands, assurance-aware result envelopes,
governance interface 2, recommendation start authority, advance contraction,
and Mermaid semantic profile 2. These are intentional beta-contract changes;
`0.6.1` would understate them.

Grammar 1 through 5 documents remain readable with their existing semantics.
For those documents, assurance is reported as not enabled. A Grammar 6
document opts into semantic commitments and must be migrated through the
preview-first sealing workflow rather than by copying or inventing hashes.

## 2. CLI migration

The existing Contract 6 command paths retain their meanings unless this guide
calls out an assurance interaction. Contract 7 adds:

```text
plan-assurance show
plan-assurance hash
plan-assurance seal
plan-assurance reseal
plan-dependency add
plan-dependency set
plan-dependency remove
task-outcome add
task-outcome set
task-outcome remove
```

Use `plan-assurance show` for the complete assurance projection and
`plan-assurance hash` for one scalar commitment used in a pinpoint manual
source repair. Hash inspection is read-only evidence; it is not a seal,
owner confirmation, or write authority. Use preview-first `seal` for initial
Grammar 6 activation and selected `reseal` only after reviewing the reported
replanning impact.

Planning dependencies default to `both`. Use `planning_only` when the plan
commitment depends on another task but execution does not, and
`execution_only` when execution depends on another task while the downstream
plan commitment remains independent. The CLI mutation commands are the normal
writer; hand-authored relation records remain validated against the same
semantic rules.

## 3. JSON consumer migration

Contract 7 consumers MUST require `cli_contract_version == 7` and inspect each
closed result's `schema_version`. The affected identities are:

| Surface | `0.6.0` / Contract 6 | `0.7.0` / Contract 7 |
| --- | --- | --- |
| document check | `Perttool.CheckResult.v3` | `Perttool.CheckResult.v4` |
| project show | `Perttool.ProjectResult.v3` | `Perttool.ProjectResult.v4` |
| dag analyze | `Perttool.AnalysisResult.v4` | `Perttool.AnalysisResult.v5` |
| dag next | `Perttool.NextResult.v5` | `Perttool.NextResult.v6` |
| direct, lifecycle, and batch mutation | `Perttool.MutationResult.v3` | `Perttool.MutationResult.v4` |
| dag advance | `Perttool.AdvanceResult.v1` | `Perttool.AdvanceResult.v2` |
| nested governance decision | `Perttool.GovernanceDecision.v1` | `Perttool.GovernanceDecision.v2` |
| plan-assurance show and hash | absent | `Perttool.PlanAssuranceResult.v1` |

The replacements are closed new schemas; do not validate Contract 7 output
against Contract 6 roots. Assurance-aware results include a closed assurance
projection or assurance impact as specified for that operation. Schema lookup
now exposes 20 root artifacts. Consumers must tolerate neither an unknown
identity nor an incomplete decisive projection.

## 4. Recommendation-authority migration

Contract 7 retains Recommendation interface 1 and the raw ranking algorithm,
but changes the normal start-authority policy to
`recommendation_v1_plus_release_gate_plus_plan_assurance_v1`. A task may
remain raw-recommended while absent from
`temporal.authority.startable_recommended_task_ids` because its enabled
assurance chain is unknown, unsealed, or mismatched.

Automation must start only IDs in `startable_recommended_task_ids` from a
complete, known, non-truncated `Perttool.NextResult.v6`. It must stop for an
unknown policy or result identity, `PTREC-*`, incomplete trace, unavailable
temporal eligibility, or an assurance safe stop. Replanning and resealing are
separate reviewed mutations; raw recommendation does not authorize either.

## 5. TypeScript migration

The package-root `CheckResult`, `AnalysisResult`, `NextResult`,
`MutationResult`, `AdvanceResult`, and `GovernanceDecision` aliases now select
the Contract 7 check type, `AnalysisResultV5`, `Contract7NextResultV6`,
`MutationResultV4`, `AdvanceResultV2`, and `GovernanceDecisionV2`,
respectively. The existing `ProjectMetadataResult` projects
`Perttool.ProjectResult.v4`. Code that narrows exact schema literals or imports
older versioned result types must update explicitly.

The package root adds `PlanAssuranceResultV1`, inspection and mutation
requests, assurance projections and impacts, and the Contract 7 assurance
services. Use the package root and bundled schema catalog rather than an
internal module path. Exact `0.6.0` remains the compatibility route for the
old aliases and closed result identities.

## 6. Grammar and governance migration

Lifecycle status, events, source spans, timestamps, derived schedules, and
formatting trivia do not enter semantic commitment hashes. Task definition,
planning dependency, accepted component seal, and outcome commitments do.
Changing a commitment invalidates dependent assurance without preventing
read-only analysis; new-task authority fails closed until the affected plan is
reviewed and resealed.

Governance interface 2 retains the preview-first, single-candidate,
scope-bound owner-assertion rule. Its decision adds assurance-aware scope and
impact data; it does not turn a hash into authentication or durable approval.
Never reuse `--accepted-by-owner` across a changed candidate, reseal, advance,
or later maintenance operation.

## 7. Advance and Mermaid migration

`Perttool.AdvanceResult.v2` composes the existing history guard independently
with assurance validation and contraction. `--force-history-loss` still
bypasses only its narrow initial history assessment; it cannot bypass an
assurance mismatch, reseal authority, governance, races, validation, or safe
write checks.

Mermaid semantic profile 2 preserves Grammar 6 assurance metadata for a
round trip. Profile 1 and plain Mermaid do not carry that metadata and must not
be used as a lossless Grammar 6 edit path. Validate the restored `.pert`
candidate before any persistence.

## 8. Pin and rollback boundary

Pin `perttool@0.6.0` to retain Grammar 5, CLI Contract 6, the old result
identities, and the old recommendation policy. This is a consumer selection,
not a runtime compatibility switch in `0.7.0`. The migration does not
authorize publication, npm `latest` movement, plan advance, or rollback of any
repository or registry state.
