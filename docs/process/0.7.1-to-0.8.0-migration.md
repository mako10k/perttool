# Migrating from `perttool@0.7.1` to `perttool@0.8.0`

- Document status: Accepted 1.0
- Date: 2026-08-07
- Source version: `0.7.1`
- Target version: `0.8.0`
- Grammar: 6, unchanged
- CLI Contract: 7, unchanged

## 1. Compatibility summary

Existing Grammar 1 through 6 documents and Contract 7 command invocations do
not require migration. Existing result identities, fields, command paths,
options, governance behavior, plan-assurance behavior, temporal authority,
history safety, and safe-write behavior retain their meanings.

Version `0.8.0` is a minor release because it adds public surfaces:

- `perttool/core` and `perttool/node` package subpaths;
- read-only command `dag history`;
- result identity `Perttool.HistoricalGraphResult.v1`; and
- its twenty-first root JSON Schema artifact.

The root runtime grows from 121 to 122 exports. The new Node facade is
key- and reference-identical to the 122-name root facade. The Core facade has
45 platform-neutral runtime exports.

## 2. Existing CLI consumers

Consumers of existing commands continue to require
`cli_contract_version == 7` and must branch on each result's
`schema_version`. No existing command changes to
`Perttool.HistoricalGraphResult.v1`.

Historical inspection is opt-in:

```sh
perttool dag history PLAN.pert --rev HEAD --history first-parent \
  --view snapshot --analysis none --format json
```

The command reads bounded immutable first-parent Git evidence. It does not
write the plan, Git state, or editor state. Three-way ancestry is unavailable
and fails closed.

## 3. Library consumers

Existing `import ... from "perttool"` consumers remain valid. New portable
consumers may import source, graph, exact-value, Help, Guide, and document-
session functions from `perttool/core`. Node.js consumers may use
`perttool/node` when filesystem, schema, hashing, Git, or safe-write adapters
are required.

Do not import private workspaces under `adapters/`. The LSP, VSIX, and MCP
packages are not public `0.8.0` package identities and are excluded from the
npm tarball.

## 4. Declaration identity correction

Task-specific mutations and lifecycle operations now select `(kind=task, id)`
even when a valid same-ID `plan_seal` appears earlier. Direct task addition
places the new task before assurance and actual records, and LSP definition
prefers the task declaration. Existing valid noncanonical declaration order
is preserved; no format or reorder migration is performed.

## 5. Rollback and channels

Pin `perttool@0.7.1` to roll back to the prior 44-command, 20-schema package
without the public Core/Node subpaths or `dag history`. Publication of `0.8.0`
moves only npm `beta`; npm `latest` remains `0.7.1` unless separately promoted
after release acceptance.
