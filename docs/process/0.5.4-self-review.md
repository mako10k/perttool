## 1. Decision

The complete `PTGOV-103` source change is suitable for a backward-compatible
`0.5.4` patch release. No blocking correctness, compatibility, package, or
release-safety finding remains.

The warning is emitted only after a valid candidate has been classified with
`applicable=false` and a non-empty `acceptedByOwner` set. It exposes likely
owner-confirmation boilerplate without changing the GovernanceDecision v1
shape or its `writeAuthorized=true` result.

## 3. Threat and scope review

The observed problem is accidental carryover of a loose owner-confirmation
assertion and expansion of its intended scope, not malicious evidence
forgery. The selected trigger directly detects the 18 ordinary-maintenance
uses among the observed 29 invocations. It intentionally does not claim to
detect the 10 governed invocations or the one invocation that failed before a
candidate existed.

This patch does not add accepted scopes, approval evidence, authentication,
signatures, durable audit, or cross-candidate comparison. Those would solve a
larger problem than the evidence currently supports.

## 4. Release safety

The user's 2026-07-30 instruction authorizes `0.5.4` preparation, candidate
acceptance, Git push, annotated tag, GitHub prerelease, npm `beta`
publication, and durable acceptance after every predecessor gate passes. It
does not authorize npm `latest` promotion.

Read-only preflight established that local and remote `v0.5.4`, the matching
GitHub Release, and `perttool@0.5.4` are absent. npm reported
`beta=0.5.3`, `latest=0.5.1`, and no `alpha` dist-tag.
