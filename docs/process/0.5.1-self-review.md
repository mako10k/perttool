# `v0.5.1` Compatibility and Source Self-Review

- Document status: Accepted 1.0
- Review date: 2026-07-30
- Reviewed source base: `92de5010568ca41affbcb0f7110295f39be4f466`
- Target version: `0.5.1`
- Release boundary: compatible CLI Contract 6 and Grammar 5 beta patch
- Related acceptance:
  [Contract 6 JSON Schema Source Acceptance](json-schema-acceptance.md)

## 1. Decision

No blocking compatibility, correctness, packaging, or release-safety finding
remains. `0.5.1` is the appropriate target: the change adds a read-only
command, package data, and lookup APIs, and corrects accepted Git metadata
syntax. It does not remove or reinterpret an existing Contract 6 surface.

The review found two acceptance-coverage gaps:

1. schema tests exercised unavailable Git results but not actual available
   `project history` and `project observe-velocity` results from a tracked
   repository; and
2. package checks verified bundled files and CLI lookup but did not consume a
   schema through the declared `perttool/schemas/*` package export.

Both gaps are corrected in the reviewed source.

## 2. Compatibility evidence

An isolated exact `perttool@0.5.0` installation was compared with the current
source.

| Surface | Result |
| --- | --- |
| Existing command descriptors | All 33 retained byte-semantically; only `schema` is added |
| Existing public exports | All 108 retained; eight schema APIs/types are additive |
| Grammar and CLI contract | Grammar 5 and `cli_contract_version=6` unchanged |
| Existing result identities | No removal, rename, or version change |
| Representative output | `document check`, `document format`, `project show`, `dag analyze`, and `dag next` are equal after excluding `tool_version` |
| Git history input | Existing fixed offsets retained; strict UTC `Z` added |

This does not claim that arbitrary undocumented object key order or prose is a
stable interface. It establishes the documented command, result, and package
compatibility boundary required by Requirements 21.7.

## 3. Correctness and completeness review

- The command-result inventory is derived from the typed Contract 6 registry.
- Seventeen command-result identities and the supported library-only
  `Perttool.OverrideDecision.v1` have exactly one root artifact each.
- Nineteen bundled files include the eighteen root artifacts and
  `Perttool.Common.v1` local definitions.
- Root artifacts use Draft 2020-12, stable `$id`, closed root objects, exact
  result identity, and exact Contract 6 identity.
- Strict Ajv validation covers representative success, warning, invalid,
  unavailable, usage-error, truncated, mutation, migration, help, guidance,
  available and unavailable history/observation, schema, and override
  results.
- CLI, public API, descriptor IDs, catalog paths, artifact `$id`, package
  contents, and wildcard export resolution are cross-checked.
- Unknown schema IDs fail without project reads, writes, Git access, or
  network access.

Some heterogeneous nested records remain governed by their owning normative
result specifications instead of being promoted to independent result
envelopes. This is intentional and does not leave a missing public root
artifact.

## 4. CI finding

The current GitHub Actions failure is reproduced with Git 2.54.0 and
`TZ=UTC`. `%cI` emits a strict UTC `Z`; the previous parser admitted only a
signed offset and returned `malformed_git_output`. The correction accepts
`Z` or `+/-HH:MM` while leaving every other read-only Git boundary intact.
The focused Git-probe and public history tests pass with Git 2.54.0 first on
`PATH`.

## 5. Release safety

Read-only preflight established that `v0.5.1`, a matching GitHub Release, and
`perttool@0.5.1` are unused. npm reports `beta=0.5.0`,
`latest=0.4.0`, and `alpha=0.1.0-alpha.2`. Protected Git, GitHub, and npm
routes are available without exposing credentials.

No external write was performed during self-review. Publication starts only
after source preparation and candidate acceptance. npm `latest` promotion
and Issue #5 closure remain separate authorization boundaries.
