## 1. Decision and scope

Select suffix-free `0.9.4` for the compatible Grammar 7 and CLI Contract 8
correction accepted as ADV-006 for Issue #19. `dag advance` must preserve all
criterion sets owned by milestones that remain in the candidate and validate
the complete final candidate before any history or persistence decision.

The same release includes the previously requested pinned jscpd duplicate and
Lizard complexity ratchets as repository and CI gates. These development gates
do not change the public grammar, CLI, schemas, exports, or runtime behavior.

## 2. Fixed execution order

The dependency order is fixed by `plans/release-0.9.4.pert`:

1. `RELEASE_094_SELF_REVIEW` freezes compatibility, reproduction, and scope.
2. `RELEASE_094_CORRECTION` accepts the source and closed regression matrix.
3. `RELEASE_094_PREPARATION` aligns version-bearing source and passes all
   local, package, duplicate, complexity, and documentation gates.
4. `RELEASE_094_CANDIDATE` accepts one clean commit and immutable tarball
   after read-only external preflight.
5. `RELEASE_094_PUBLISH` pushes the exact release commit and tag, requires
   Node.js 22 and 24 CI, creates one GitHub prerelease, and publishes the same
   tarball once to npm `beta`.
6. `RELEASE_094_ACCEPTANCE` independently verifies durable public identity,
   installed behavior, rollback, Issue closure, and canonical plan advance.

## 3. Candidate and mutation gates

Before the first external write:

1. require clean committed source identifying `0.9.4` in every maintained
   version surface;
2. pass the complete Node.js 22 repository, static-analysis, documentation,
   self-use, private-adapter, temporary-link, and isolated-package gates;
3. establish that local and remote `v0.9.4`, its GitHub Release, and
   `perttool@0.9.4` are absent;
4. establish `beta=0.9.3`, `latest=0.9.0`, and no `alpha`;
5. freeze one tarball outside the worktree with its exact file count, sizes,
   SHA-256, integrity, and installed Issue #19 behavior; and
6. stop if source, artifact, route, authorization, or external baseline
   changes.

The external mutation budget is one `main` push, one annotated-tag push, one
GitHub prerelease creation, one npm `beta` publication, one Issue evidence
comment and closure, one priority-label removal, and the separately verified
work-in-progress branch push after merging the release history. An ambiguous
non-idempotent response is never retried without readback.

## 4. Durable acceptance and remaining boundaries

Acceptance requires matching release commit and peeled tag, successful CI,
byte-identical retained, GitHub, and npm tarballs, registry integrity and
metadata, exact and beta isolated installations, the real Issue #19 replay,
unchanged Contract 8 identities, and an exact `0.9.3` rollback installation.

Only after those facts are durable may Issue #19 be closed while retaining
`bug` and removing `priority:P0`, and this release plan be canonically
advanced. npm `latest` remains `0.9.0`. No unrelated plan is advanced.

## 5. Restart rules

- A source change after candidate acceptance invalidates the candidate.
- A changed registry, tag, Release, route, or CI baseline requires readback
  and reassessment before any write.
- A failed predecessor gate blocks every downstream operation.
- Publication is never retried solely because of short registry propagation;
  durable state is read first.
