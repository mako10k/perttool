# `v0.5.5` Governed-Preview Warning Beta Patch Release Procedure

- Status: Accepted 1.0
- Decision date: 2026-07-30
- Target version: `0.5.5`
- Product maturity: beta
- GitHub channel: prerelease
- npm publication tag: `beta`
- Expected pre-publication tags: `beta=0.5.4`, `latest=0.5.1`, no `alpha`
- Versioning: [ADR 0003](../adr/0003-beta-versioning.md)
- Self-review: [`0.5.5-self-review.md`](0.5.5-self-review.md)
- Release plan: [`release-0.5.5.pert`](../../plans/release-0.5.5.pert)

## 1. Decision and scope

Select suffix-free `0.5.5` for the compatible CLI Contract 6 and Grammar 5
patch that publishes `PTGOV-104`. A valid applicable preview with one or more
caller-asserted owner confirmations receives the stable warning. Default
preview success and its candidate and decision remain available; existing
`--warnings-as-errors` returns exit 1 while retaining both.

The patch retains Grammar 5, CLI Contract 6, all 34 commands, all option
spellings, runtime and schema identities, payload meanings, persistent
authority, safe-write controls, and package-root values. It does not create
Contract 7, Grammar 6, a new result field, accepted-scope or evidence options,
authentication, cross-candidate state, or an npm `latest` promotion.

## 2. Work packages and authority

The dependency order is fixed by `plans/release-0.5.5.pert`.

1. `RELEASE_055_SELF_REVIEW` verifies the observed threat, trigger,
   compatibility, applicable mutation paths, tests, and release safety.
2. `RELEASE_055_PREPARATION` aligns version-bearing source, release
   documentation, self-use checks, tests, and goldens.
3. `RELEASE_055_CANDIDATE` accepts one clean commit and one immutable tarball
   after complete local and read-only external preflight.
4. `RELEASE_055_PUBLISH` pushes the release commit and annotated tag, creates
   the GitHub prerelease, and publishes the same tarball once to npm `beta`.
5. `RELEASE_055_ACCEPTANCE` records durable identity and public-channel
   verification.

The user's 2026-07-30 release instruction authorizes this complete named
sequence once every predecessor gate passes and no blocking finding remains.
It does not authorize npm `latest` promotion or a different version, tag,
artifact, or publication channel.

## 3. Source-preparation gate

Update and verify together:

- `package.json`, root lockfile entries, and `src/version.ts`;
- a dated `0.5.5` CHANGELOG section and comparison link;
- README current-channel and compatibility guidance;
- requirements, design, warning guidance, release procedure, self-use
  registry, plan goldens, and release tests; and
- package inclusion, command/schema/API identity, installed workflow, and
  beta-only publication normalization.

Run under Node.js 22:

```sh
npm ci
npm run check
git diff --check
```

No external write is allowed in this gate.

The prepared source passed this gate under Node.js 22.22.3 on 2026-07-30:

- 672 tests passed;
- the English baseline checked 508 text files and three allowlisted lines;
- documentation checks passed for 125 Markdown files and seven normative PERT
  examples;
- check, analyze, and complete NextResult v5 validation passed for all 26
  self-use plans;
- the temporary-link and isolated installed-package workflows reported
  `perttool 0.5.5`; and
- the dry-run package contained 491 files and normalized only to npm `beta`.

`git diff --check` also passed. The preparation mutation changed one line in
`plans/release-0.5.5.pert`, from 5,181 to 5,195 bytes, at
2026-07-30 21:37:09 +09:00. It was governance-not-applicable and used no
owner-confirmation assertion. No external write occurred.

## 4. Candidate gate

Before the first external write:

1. require clean committed source with package, lockfile, CLI version, and
   intended tag equal to `0.5.5` and `v0.5.5`;
2. pass the complete repository and isolated-package gates under Node.js 22;
3. reconfirm that local/remote `v0.5.5`, the GitHub Release, and
   `perttool@0.5.5` are absent;
4. record current npm `beta` and `latest` and confirm `alpha` remains absent;
5. verify protected Git, GitHub, and process-scoped npm routes without
   displaying credentials;
6. build one tarball outside the worktree, record its modification time, file
   count, packed and unpacked sizes, and digests, and retain it unchanged; and
7. stop if source, artifact, authorization, or external baseline changes.

The release commit is the commit that records candidate acceptance. Because
repository-only records are excluded from the package, later durable records
must not regenerate or replace the accepted tarball.

## 5. Authorized PUBLISH

Only after candidate acceptance:

1. push and verify the clean release commit on `origin/main` through
   `secdat exec git`;
2. require successful Node.js 22 and 24 CI for that commit;
3. create and push annotated `v0.5.5`, then verify its peeled target;
4. create a GitHub prerelease with the retained tarball and `SHA256SUMS`;
5. download, compare, install, and exercise the GitHub asset in isolation;
6. inject `NPM_TOKEN` only into `scripts/publish-npm.sh --publish` and publish
   the downloaded GitHub tarball exactly once to npm `beta`; and
7. verify `beta=0.5.5`, unchanged `latest=0.5.1`, and absent `alpha`.

Do not retry an ambiguous external mutation. Read back durable state first
and resume only a demonstrably missing idempotent step.

Exact publication evidence is recorded in
[`0.5.5-publish.md`](0.5.5-publish.md).

## 6. Durable acceptance

Acceptance requires:

- local, remote-main, release commit, and peeled tag identity;
- byte-identical candidate, GitHub, and npm tarballs;
- registry integrity, metadata, `beta=0.5.5`, unchanged `latest=0.5.1`, and
  absent `alpha`;
- successful isolated installation from both public channels;
- `--version`, Contract 6 help and Guide, Grammar 5 checking, `PTGOV-104`
  default and strict preview behavior, schema lookup, package-root lookup, and
  beta-only publication guard;
- successful candidate CI on Node.js 22 and 24; and
- exact commands, outputs, URLs, sizes, timestamps, diffs, and digests in
  separate PUBLISH and acceptance records.

The accepted artifact is immutable. Durable records and any residual plan
advance occur later and do not change the release tarball.

Independent readbacks are recorded in
[`0.5.5-release-acceptance.md`](0.5.5-release-acceptance.md).
