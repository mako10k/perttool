## 1. Version decision

Accept suffix-free `0.9.0` for the breaking public boundary after published
`0.8.1`. The current source changes grammar, CLI Contract, commands, result
identities, schemas, start and advance authority, and migration behavior.
`0.8.2` would understate this compatibility boundary, while `1.0.0` remains a
separate stable-series decision.

The package remains a pre-1.0 beta, uses a GitHub prerelease, and publishes
only to npm `beta`. Publication must leave independently managed
`latest=0.8.1` unchanged.

## 3. Semantic and migration boundary

Grammar 7 adds criterion-set, receipt, and migration declarations. Contract 8
keeps graph closure separate from milestone outcome acceptance and blocks
canonical advance atomically unless each affected non-grandfathered milestone
is accepted. Check, analysis, Next, mutation, advance, historical DAG, Help,
Guide, schemas, root exports, LSP, VSIX, MCP, and installed-package behavior
must agree on that model.

Existing Grammar 1 through 6 documents remain readable. Contract 8 acceptance
mutation and canonical advance require Grammar 7. Committed in-place migration
records an exact grandfather baseline and performs no inferred acceptance.

## 4. Included corrections and exclusions

The release includes Point-default project initialization, actionable legacy
day/hour migration guidance, the Issue #9 receipt-placement correction, the
Issue #11 consecutive-terminal-deletion correction, and current Help and
documentation alignment. The compact duration presentation remains private
VSIX behavior and does not change public npm semantics.

Private LSP, VSIX, and MCP workspaces remain build and acceptance inputs but
are excluded from the public tarball. Public VSIX identity, Marketplace and
Open VSX publication, editor mutation, MCP mutation, npm `latest`, plan
advance, Issue mutation, and unrelated backlog work remain outside this
release.

## 5. Authority and result

This gate changes no package version, Git ref, remote, tag, Release, registry,
dist-tag, VSIX publication state, plan advance state, or Issue. Its successor
is only `RELEASE_090_INPUT_READINESS`.
