# `0.5.5` to `0.6.0` Advance Result Migration

- Status: Accepted 1.0
- Source package: `perttool@0.5.5`
- Target package: `perttool@0.6.0`
- Grammar: unchanged Grammar 5
- CLI contract: unchanged Contract 6
- Affected command: `dag advance`
- Source result: `Perttool.MutationResult.v3`
- Target result: `Perttool.AdvanceResult.v1`

## 1. Why the package minor changes

Published `0.5.5` returns the closed `Perttool.MutationResult.v3` identity for
`dag advance`. Adding history evidence to that identity would violate its
Draft 2020-12 schema. Version `0.6.0` therefore selects a new closed
`Perttool.AdvanceResult.v1` root for that existing command.

The target retains every prior mutation, write, governance, lifecycle, and
advance field and adds one required nullable `history_guard` field. All other
commands retain their `0.5.5` result identities. Grammar 5, CLI Contract 6,
command paths, and existing option defaults remain unchanged.

## 2. JSON consumer migration

Consumers MUST inspect `schema_version` before validating or automating on an
advance result:

| Package | `dag advance` result | History field |
| --- | --- | --- |
| `0.5.5` | `Perttool.MutationResult.v3` | absent |
| `0.6.0` | `Perttool.AdvanceResult.v1` | required, nullable `history_guard` |

Do not validate a `0.6.0` advance result against the old closed mutation
schema. Discover or load `Perttool.AdvanceResult.v1` from the local schema
catalog. Direct, lifecycle, and batch mutations continue to use
`Perttool.MutationResult.v3`.

`history_guard=null` is distinct from a populated guard whose status is
`not_applicable`. A changed destructive in-place write returns a populated
guard and persists only after its status and every retained safe-write gate
allow the request.

## 3. CLI migration

Ordinary preview syntax is unchanged. A destructive in-place write now
requires recoverability proof from the exact current `HEAD` path and stage-0
index. Unsafe or unavailable proof fails closed before replacement.

`--force-history-loss` is new and valid only with `dag advance --write`. It is
an exceptional exact-request input, not a session setting. It bypasses only an
initial history assessment with status `blocked`; it does not bypass owner
authority, warning policy, expected digests, source or repository races,
candidate validation, atomic replacement, or post-write verification. Never
carry it to another candidate.

The ADV-002 correction requires no caller action. Preview, separate output,
and in-place write now use the same repository-clean candidate and need no
formatter or second whitespace edit.

## 4. TypeScript migration

The package-root `AdvanceResult` alias now names `AdvanceResultV1` and exposes
`historyGuard`. `AdvanceResultV1`, `AdvanceHistoryGuardV1`, its status/cause
types, and `ADVANCE_RESULT_SCHEMA_VERSION` are public.

The older exported name `AdvanceResultV3` remains as a deprecated
source-compatibility alias for `AdvanceResultV1`; new code uses
`AdvanceResultV1`. Code that narrows the exact `schemaVersion` literal must
update from `Perttool.MutationResult.v3` to `Perttool.AdvanceResult.v1`.

## 5. Pin and rollback boundary

Exact pin `perttool@0.5.5` retains the prior result identity and prior write
behavior. Installing that old artifact is an explicit consumer choice; it is
not a runtime mode of `0.6.0`. This migration does not authorize npm `latest`
movement or any rollback mutation.
